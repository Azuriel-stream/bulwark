# Bulwark: design

Bulwark merges three standalone WoW: Forever addons into one: TankAlertForever (Alerts), TankAuditForever (Audit)
and TankMarkForever (Marking). Each becomes an **area** with its own tab, on/off switch and modules. The window's
layout (banner, tab bar, side menu, pages) is Bulwark's own code and art.

## Layout

```
Bulwark/
├── Bulwark.toc        SavedVariables BulwarkDB, PerCharacter BulwarkCharDB
├── Core/
│   ├── Errors.lua     error recorder (first in the TOC): ScriptErrorsFrame post-hook -> BulwarkDB.errors
│   ├── Init.lua       namespace, Print/Debug, message bus (On/Fire), module registry, lifecycle, blocked-action recorder
│   ├── Config.lua     defaults + merge for BulwarkDB / BulwarkCharDB
│   ├── Utils.lua      secret-safe helpers shared by every area
│   └── Areas.lua      area registry, on/off switches, legacy-addon guard
├── Locales/           L table (missing key = key), enUS
├── UI/
│   ├── Kit.lua        colours and widgets: Fill, Border, FadeLine, Text, Button, Switch, Checkbox, Slider, Card
│   ├── Window.lua     the window (lazy), tabs, side menu, lazy pages, scale/position
│   ├── Settings.lua   Settings tab: Areas, Window, Debug, About
│   ├── Minimap.lua    minimap button (round and square minimaps), addon compartment callback
│   └── Commands.lua   /bwk, /bulwark
├── Areas/<Area>/      Area.lua (registration + pages); the area's modules and data join here when ported
├── Media/             icon.tga, minimap.tga, tab_*.tga (generated by the workspace's make-icon.ps1)
└── tests/             wowsim headless tests (not in the TOC)
```

## Areas and modules

- `NS:RegisterArea{ key, order, title, desc, icon, legacy, switch, pages, command }`; `NS:AddPage(areaKey, page)`
  with `page.build(page, parent)` (called once, on first show) and `page.refresh(page)` (every show).
- `NS:RegisterModule(name, areaKey)`: `OnInitialize` at ADDON_LOADED for every module; `OnEnable`/`OnDisable`
  when the area starts or stops (login, switch). Core modules (no area) are enabled at login.
- Switches are saved in `BulwarkDB.areas[key].enabled` and can't change in combat (areas own secure frames).
- **Legacy guard:** an area with `legacy = "<AddonName>"` doesn't start while that addon is loaded, so a player
  moving over never gets doubled alerts or two sets of marking keys.
- `/bwk <area> <args>` goes to `area.command(args)`.

## Rules

- No Blizzard dropdown menus (they crashed the client); radio rows or our own pop-up lists.
- The window is plain frames: it opens, switches tabs and closes in combat. The close button calls `Hide()`
  directly (the template's handler is refused in combat).
- Secure frames (Audit tiles, Marking buttons) are never parented to the window.
- Secure buttons are named `BWK_*`.
